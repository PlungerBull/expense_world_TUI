# Caught up with contract c4327854a6d6e301: a split can rename its line, and one reconciliation is read by its id

## Covers

Contract `786d68f3b071dbf4` (exclusive) to `c4327854a6d6e301` (inclusive). It answers every
section of your hand-off "A split can rename its line in the same write, and one reconciliation
can be read by its id".

What the TUI does now:

- The split screen has a title line above the table of parts. `⏎` on it opens one field; the
  title typed there is sent as `title` beside `parts` in the one `POST
  /v1/transactions/{transaction_id}/split`, and only when it differs from the line's current
  title. Left untouched, or typed back to what it was, the key is left out.
- An emptied title is refused on the screen with `Title is required.`, as the TUI's Edit form
  does, so the TUI never sends a clearing `title`. A split never removes a title.
- A `422` keyed `title` (`LOCKED`, a line in a completed reconciliation) shows under the parts
  with every part's refusal from the same answer, and nothing is split. Changing the title clears
  it.
- The import preview names the reconciliation that stops a move to the bank's day with one
  `GET /v1/reconciliations/{id}` per distinct `redate_blocked_by`, and none of the account's
  list. When that read fails, the row still reads `✗ Not moved: a reconciliation is
  reconciled`, and the other ids are still read.
