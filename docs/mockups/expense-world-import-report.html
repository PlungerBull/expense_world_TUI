Import · the report

The import door's preview, and the screen after importing, as one table of the file's rows with two more columns: a mark (✓ or ✗) and a reason from a short fixed list. Every outcome of an import — new, already there, modified, stopped, left out — is a reason, so a new engine feature adds a reason, not a new note.

It replaces the preview's match column and the notes under the summary. The example file has one row of each reason: row 7 WONG SAN ISIDRO is on 03 Oct in the ledger and 04 Oct in the bank, and moves; row 9 TAMBO MIRAFLORES would move from 30 Sep to 01 Oct, but its reconciliation Septiembre 2026 is completed. The rows are invented. Use the button at the top right for a light terminal.

Questions for the owner

  1. Pane 1 · what does ✓ mean?
    • 1A: ✓ only when the row made a new transaction. A row already in the ledger gets ✗, so a re-imported file is mostly ✗ though nothing is wrong.
    • 1B (recommended): ✓ when the row is in the ledger after the import — new, already there, or modified. ✗ only for a row left out (closed period, before 2026, unreadable), so ✗ always means “look at this”.
  2. Pane 2 · does the reason say what changed?
    • 2A: the reason alone — Modified existing transaction.
    • 2B (recommended): the reason, then dim what changed — Modified existing transaction · day 03 Oct → 04 Oct, Not modified · Septiembre 2026 is reconciled, keeps 30 Sep. Full detail of what happened, row by row.
  3. Pane 3 · under the table. The table lists the file's rows, so a transaction in the ledger that the file does not have cannot be a row of it. Today it shows only in “days where the file and the ledger disagree” (a possible duplicate).
    • 3A (recommended): keep that block under the table, on the preview and after importing.
    • 3B: the table alone.
  4. Pane 4 · after importing. The same table, with the same reasons and marks, under ✓ 5 rows imported; the column is headed what happened instead of reason. Agree, or say what differs.
  5. The reasons' words (the box under these questions). Change any of them, or agree.
The reasons — the whole list, one per row. The words after · are the detail (question 2). 
  ✓  New                             · added to the ledger
  ✓  Already in the ledger             found by operation number or by the same day and amount; nothing changed
  ✓  Modified existing transaction   · took the bank's title / got the operation number / day 03 Oct → 04 Oct
  ✓  Not modified                    · Septiembre 2026 is reconciled, keeps 30 Sep  (the move to the bank's day was stopped)
  ✗  Closed period                   · Agosto 2026
  ✗  Before 2026
  ✗  Couldn't read the row           · the date is empty / the operation number is on two rows
Marks as in 1B. A row modified two ways says both: Modified existing transaction · took the bank's title, day 03 Oct → 04 Oct.
