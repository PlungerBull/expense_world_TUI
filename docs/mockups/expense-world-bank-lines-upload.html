Bank upload · rows the ledger has, and days that disagree

The bank upload behind the LOG bar (drop a BCP file, pick its account, preview, import) on the new engine. What changes: rows the ledger already has can take the bank's title, the summary reads the engine's counts, the “no file row matched” warning becomes the engine's list of days where the file and the ledger disagree, and a new refusal when something changes a row while the import runs.

Everything else on these screens is as you approved it in the import door. The rows are invented. Use the button at the top right to see the page on a light terminal.

1 · Rows the ledger has, and the ones that take the bank's title — the preview, before anything is written

The engine now says, for every row it finds in the ledger, whether that ledger row will take the bank's title. Example: you typed Uber on 09-14, and the bank calls it UBER TRIP. The ledger row is found by its day and amount, and on import its title becomes UBER TRIP, with Uber kept as its note when it has none. Row 6 is a purchase you split in two parts: the engine finds it by the same rule, and both parts take the title. The count at the end of the summary is the engine's own count, like every count on this line.

2 · The days where the file and the ledger disagree — replacing the “no file row matched” warning

The engine now checks every day of the file, from its first date to its last, and lists each day where the file's total and the ledger's total (after this import) are not the same. Both totals are signed: money in is positive, money out negative. For each such day it names the file rows it did not find in the ledger and the ledger rows no file row claimed. Three days in this file:
· 09-12: you typed Farmacia -42.00, the bank says -42.90. Different amounts, so the bank's row is new and the ledger would hold both.
· 09-10: you typed Cine -28.00 a day before the bank posted it on 09-11. A row a day off is new (you accepted this on 2026-10-16), so 09-10 shows your row left over.
· 09-07: the ledger has two Cafe -3.50, the file one.
It is a report only: nothing on it changes what ⏎ writes.

4 · Something changed a row while the import ran — CONFLICT, CONCURRENT_CHANGE

You press ⏎ Import 9 rows. Just before the engine writes, it checks every row it found again. If something else split, deleted or changed one of those ledger rows in the meantime (another screen, another device), it writes nothing and says which file row. The engine's two sentences here are stand-ins: its exact words show once it is built.
