Number format

Amounts are read and shown one way today: a dot for decimals, a comma between thousands (1,234.56). A comma typed as a decimal is dropped, so -1,5 saves -15.00 without a word. Here the format becomes a setting on your account, kept by the engine so every device agrees, and every amount you type or see follows it.

The questions are panes 1 and 3; pane 2 shows what follows from them. Amounts, names and the engine's words are invented. Drawn at 80 columns.

1 · Where the format is set — System ▸ Auth & profile · pick A or B

2 · Every amount follows it — no pick: what you see under each format

The ledger, Home, statements, the forms and the toasts all write amounts the same way. A form's amount line, opened to edit, shows it in the format too. An amount inside the engine's own words (a refusal naming a limit, say) stays as the engine wrote it.

3 · An amount that does not fit the format — the format is 1,234.56 here · pick A or B

A mark between thousands is always followed by three digits (1,500), so -1,5 cannot be one: under 1,234.56 it can only be someone typing a decimal comma. Today it saves -15.00. Either way it never does again.

A · Refused, naming the formatrecommended

Nothing is sent and the line stays open. The same goes for -1.234,56, the other format, typed here. -1,500 and -1500 are both fine.

B · Read as a decimal where it can only be one
expense · LOG bar
 LOG ▸ almuerzo -1,5 $BCP-5678▍

 almuerzo  -1.50  PEN  BCP-5678  today

-1,5 and -1,50 read as -1.50, while -1,500 stays one thousand five hundred. One more digit changes the amount a thousandfold, with no warning.
