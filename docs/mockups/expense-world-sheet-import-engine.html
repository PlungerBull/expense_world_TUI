Sheet import · through the engine

expense import sheet sends your spreadsheet to the engine whole; the engine reads it and answers. This is what the terminal prints. Every name, row and amount here is made up; the refusal words stand in for the engine's own, which the app shows as the engine writes them.

As you answered: the engine counts rows only once every account, category and hashtag the sheet uses exists, so a step of its own creates the missing names, and the dry run never writes (question 4, C). --account-name stays and is remembered; an account used in two currencies is two accounts with the same name.

The flow, for an import into an empty ledger: dry run (lists what's missing) → create the names → dry run (now with counts) → --apply.

Pick one letter for the step's name and one for --apply with names missing, and say yes or no to the screens. The button at the top right shows a light terminal.

Pick 1 · the step's name

What you type to create the missing names, and the line the first dry run ends with.
A · a flag on the same command recommended
zsh
$ expense import sheet libro.xlsx --create-names
Same command as the dry run and the apply, one word more; import sheet stays the only command.
B · a command of its own
zsh
$ expense import names libro.xlsx
Reads as its own job, but adds a second command to remember.
C · a shorter flag
zsh
$ expense import sheet libro.xlsx --prepare
Shorter, but says less about what it writes.

Screen 5 · a sheet with bad rows — any of the three commands
One bad row stops the whole thing. Every refusal is listed, in the engine's words; rows refused alike share one line. The create step checks the sheet first too, so a refused sheet creates no names.
