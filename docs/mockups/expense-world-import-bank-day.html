Import · the bank's day

The import door's preview and its ✓ N rows imported screen, when a file row is found in the ledger by its operation number but the bank has it on another day. Importing moves that transaction, every part of it, to the bank's day, and the preview says so before anything is written. A completed reconciliation stops the move: the transaction keeps its day, still found, and the rest of the file imports as usual.

The example in every pane: WONG SAN ISIDRO -100.00, operation number 123456, is on 03 Oct in the ledger and on 04 Oct in the bank file. Everything else on these screens is as built. The rows are invented. Use the button at the top right to see the page on a light terminal.

Questions for the owner

  1. Pick one letter for pane 1 and one for pane 2.
    • 1A (recommended): the move is written in the match column, where +code and +title already sit. The date column stays a clean column of dates.
    • 1B: the move is written in the date cell itself, so the eye catches it in the date column.
    • 2A: the whole reason is in the match column. One place to look, but the row needs a terminal about 120 columns wide; narrower, its end is cut with ….
    • 2B (recommended): a short mark on the row, and the reconciliation's name and the reason in one note under the summary. The row stays as wide as the others.
  2. How are the two days written? Every other date on the preview reads 2026-10-04; the move is drawn as 03 Oct → 04 Oct.
    • A (recommended): 03 Oct → 04 Oct, as drawn. Short, and a move is only ever a day or two.
    • B: 2026-10-03 → 2026-10-04, the same way as the date column. Longer: on a narrow terminal the match cell is cut.
  3. The line on the imported screen. The line above it today reads 2 rows in the ledger took the bank's title.
    • A (recommended): 1 transaction moved to the bank's day, as drawn. “Transaction” is the app's word for a ledger row.
    • B: 1 row in the ledger moved to the bank's day, worded like the line above it.
  4. The note in 2B (new words): ! row 11 keeps 03 Oct, the ledger's day: Septiembre 2026 is completed.
    • A (recommended): with a second line saying what to do, Revert it and import the file again to move it to 04 Oct., the way the closed-period note says “revert the period to add them”.
    • B: the first line alone.

2 · A transaction keeps its day — a completed reconciliation stops the move

Row 11 stays on 03 Oct because the card's reconciliation Septiembre 2026 (its statement runs 2026-09-04 → 2026-10-03) is completed; the row is still found, and the other rows import.

The app names the reconciliation by reading it. The row is not moved, so nothing is added to the summary. Because the transaction stays a day off, the days where the file and the ledger disagree list both days, with no row under them: the file row was found. A card file names its account on each day, as today.
