When the engine says no: what to do next

When the engine refuses something you asked for, the app shows a note in the bottom-right corner. Its first lines are always the engine's own words. You already approved, for deletes, a blank line and then one line of the app's own saying what to do next. You decided on 2026-10-14 that every refusal the engine explains gets that line too. This page proposes the wording for each new line.

Each refusal is drawn once, on the screen where you would actually meet it. The table below lists every other screen where the same refusal can appear, and the same line shows there. Where a wording has a real choice, both are drawn as A and B with one marked recommended. The first group is already approved and stays word for word. It is shown only so the page is complete.

The engine now also adds a second line under its answer, naming the thing it refused (for example account_id: …). The app shows the engine's words whole, so that line appears in every note. Only the account refusal (screen 1) uses the engine's real wording. Every other engine sentence on this page is a stand-in. The rows are invented.

4 · Another row has the same bank operation number — one wording

Rows that came from a bank file carry the bank's operation number, and one account cannot hold the same number twice. You meet this when you move a row to another account that already has a row with that number (on the row's Edit form, or with b on selected rows), or when a bank file brings one in. Usually it means the row is already there: a duplicate.

5 · Something else changed it at the same moment — a rare race, fixed by trying again

The engine refused because, in the same instant, something else was changing the same thing (another delete of it, or the engine creating @Pendiente or @Opening for you the first time it is needed). Nothing is wrong: trying again works. The choice is whether the line names the key for the screen you are on, or says the same words everywhere.

6 · One of your categories has a built-in category's name — rare, and only you can fix it

The engine makes @Pendiente and @Opening for you the first time it needs them. If one of your own categories already has that name, it cannot, and refuses. You meet it saving an opening balance, saving the LOG bar, or importing a bank file. The fix is to rename your category. Drawn on the account's Edit form, with the opening balance half refused (the note you confirmed for it).

Not shown, and why
  • A sign-in key that cannot be shown twice. Only creating a new sign-in key can draw it, and the app never creates one.
  • A duplicate when the LOG bar saves. When the LOG bar sends rows again after a half-finished save, the engine says some are already there. That means they are saved: they get their ✓, and no note shows.
  • A duplicate bank operation number when the LOG bar saves. A typed line never carries a bank operation number, so the LOG bar cannot draw it.
  • Moving a row while assigning it to a reconciliation. Ticking rows on a reconciliation never changes their account, so it cannot draw screen 4.
